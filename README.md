# سَـوَاد وناسة | Suwad Wanasa

منصة ألعاب اجتماعية عربية بطابع عراقي: **لَمّة، ضحك، وخَبْصة!**

## أقسام المشروع
- واجهة عربية RTL متجاوبة مع الهاتف والكمبيوتر، مع نسخة PWA قابلة للتثبيت.
- ألعاب محلية على جهاز واحد، وألعاب تدريب ضد أوراس بحسب الطور المتاح.
- غرف أونلاين تستخدم Supabase Auth وPostgres وRealtime ومحركات خادمية لبعض الألعاب.
- حسابات وأصدقاء ومراسلات خاصة وشات عام وغرف لعب.
- مساعد أوراس للألعاب عبر Edge Function، وخدمة صوت مستقلة؛ وجود الكود في الفرع لا يعني أن كل إصدار منه منشور أو متوافق مع الموقع الحي.
- الملفات الأساسية للواجهة تُخزّن للعمل دون اتصال؛ ميزات الغرف والحسابات والمساعد الصوتي تحتاج اتصالاً بالإنترنت.

## إعداد الخلفية
يستخدم المشروع Supabase Auth وPostgres وRLS وEdge Functions. لا تشغّل `supabase-schema.sql` فوق قاعدة قائمة، ولا تطبق ترحيلاً على الإنتاج اعتماداً على اسم الملف وحده. راجع [SUPABASE-SETUP.md](SUPABASE-SETUP.md)، وتحقق من سجل الترحيلات وتوافق الواجهة والمحرك قبل أي تغيير.

لا تضع `service_role` أو أي مفتاح سري في ملفات الواجهة أو مستودع GitHub. مفاتيح المزوّدين تُحفظ في أسرار Edge Functions فقط.

## القواعد حسب نمط اللعب
- **حيّة ودرج:** اللوحة الخادمية تحفظ مساراتها حتى تستخدم الواجهة والخادم التوزيع نفسه. عدد الثعابين من ٢ إلى ٥ وعدد السلالم من ٢ إلى ٥، مع حد أقصى ٩ مسارات مجتمعة؛ لا تفترض ستة من كل نوع.
- **الدومينوا:** طور الدبل ستة، ٢٨ قطعة، مع قواعد البداية والسحب والتمرير واختيار طرف السلسلة بحسب إصدار المحرك.
- **UNO:** رزمة قياسية من ١٠٨ كروت في محرك التدريب، مع قواعد خاصة مثل التخطي والعكس والسحب ونداء UNO؛ يجب اختبار تطابق قواعد الأونلاين مع الخادم قبل وصفه بأنه مكتمل.
- **الطاولي المحلية:** تستخدم `tavla-rules.js` قواعد Backgammon الكلاسيكية: رقعة ٢٤ نقطة، ١٥ حجراً لكل لاعب، البار، الضرب، الدبل، والإخراج.
- **الطاولي الأونلاين:** لا تخلطها مع الطاولي المحلية. مصدر SQL الخادمي الذي دُقّق في ٨ نوفمبر ٢٠٢٦ ما زال يحتوي عقد الحركات القديم `roll / select-piece / move-piece` ولا يحتوي تنفيذ `move-tavla` الذي ترسله واجهة التطوير. لذلك لا نعلن تطابق القواعد الكلاسيكية أونلاين ولا نطلق واجهة هذا العقد قبل إضافة ترحيل خادمي واختبارات PostgreSQL له.
- بقية الألعاب لها محركات أو أطوار مختلفة؛ نجاح اختبار لعبة محلية لا يثبت تلقائياً اكتمال طورها الأونلاين.

## المحركات والأمان
- تخمين الرقم له محرك خادمي منفصل؛ لا تكشف الرقم السري للمتصفح ولا تقبل هوية اللاعب من جسم الطلب.
- غرف المحرك الثالث تستخدم إجراءات خادمية وسجلات أحداث وحالة خاصة للاعبين في الألعاب التي يدعمها المحرك.
- قد تبقى غرف قديمة على الإصدار الأول؛ لا تُرقَّ ولا تُحذف أثناء جولة نشطة. ترقية الغرف يجب أن تتم عبر آلية المحرك بعد التحقق من حالة الجولة.
- لا تعتبر نجاح CI دليلاً كافياً على سلامة الأونلاين. يلزم اختبار PostgreSQL للعقد الخادمي، ثم اختبار حسابين على جهازين، ثم اختبار الهاتف الفعلي.

## التحقق والنشر
GitHub Actions يفحص الصياغة والأصول وبعض قواعد الألعاب وسياسات المحرك. بعض ملفات SQL smoke tests تحتاج تشغيلها في قاعدة اختبار معزولة؛ لا تفترض أن مجرد وجودها يعني أنها نُفذت في CI أو على الإنتاج.

يُنشر الموقع العام من فرع النشر المحدد في إعدادات GitHub Pages. فرع التطوير وطلبات السحب لا تغيّر الموقع العام تلقائياً إلا إذا كانت إعدادات النشر تربطها بذلك. لا نعلن رابط إصدار جديد قبل نجاح النشر والتحقق من النسخة المنشورة.
