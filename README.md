# سَـوَاد وناسة | Suwad Wanasa

منصة ألعاب اجتماعية عربية بطابع عراقي: **لَمّة، ضحك، وخَبْصة!**

## أقسام المشروع
- واجهة عربية RTL متجاوبة مع الهاتف والكمبيوتر.
- PWA قابلة للتثبيت، ونسخة مخزنة للواجهة والملفات الأساسية دون اتصال.
- ألعاب محلية على جهاز واحد: تخمين الشخصية، تخمين الرقم، برا السالفة، منو الأكثر، وممنوع إي ولا.
- ألعاب غرف أونلاين مبسّطة: حيّة ودرج، دومينوا، طاولي مبسّطة، كروت الألوان، تحدّي الأسئلة، والدولاب المشترك.
- حسابات بأسماء مستخدمين ومعرّفات صداقة، طلبات صداقة، رسائل خاصة، وشات عام محفوظ على Supabase.
- شروحات مصوّرة وصوتية للأطوار المتاحة.

## إعداد الخلفية
يستخدم المشروع Supabase Auth وPostgres وRLS. للإعداد الجديد شغّل `supabase-schema.sql` كاملاً، وفعّل Anonymous Sign-Ins، واضبط Site URL، ثم ضع Project URL والمفتاح العام فقط في `backend-config.js`.

للمشاريع القديمة شغّل الترحيلات المطلوبة، وخصوصاً `supabase-public-chat-migration.sql` للشات العام و`supabase-wheel-migration.sql` للدولاب. راجع [SUPABASE-SETUP.md](SUPABASE-SETUP.md).

## حدود التنفيذ الحالية
بعض ألعاب الغرف نسخ مبسّطة. الدومينوا وضع مفتوح تظهر فيه القطع، والطاولي ليست تطبيقاً كاملاً لقواعد الطاولة، وبعض أطوار الأسئلة والتصويت تعتمد التحكيم والاتفاق بين اللاعبين بدلاً من احتساب آلي كامل. لا نصف هذه الأطوار بأنها مكتملة القواعد قبل استكمالها واختبارها.

## التحقق والنشر
كل push إلى `main` يشغّل GitHub Actions لفحص صياغة JavaScript، الروابط المحلية، ملفات PWA، تطابق مفاتيح الألعاب مع SQL، ووجود واجهة الشات العام وسياساتها. نجاح هذه الفحوصات لا يغني عن اختبار حسابين حقيقيين على جهازين.
يُنشر الموقع عبر GitHub Pages. لا تضع مفتاح `service_role` أو أي سر في ملفات الواجهة.
## أمان محرك الغرف والذكاء الاصطناعي
- لعبة **تخمين الرقم** تستخدم بوابة Edge Function موثّقة بجلسة اللاعب؛ هوية اللاعب تؤخذ من JWT الموثّق ولا تُقبل من جسم الطلب.
- الرقم السري يُولّد على الخادم ويُخزّن في جدول خاص لا يملك المتصفح صلاحية قراءته. التخمينات والتحقق من الفائز وتحديث النقاط تتم على الخادم مع حماية من تكرار التخمين السريع.
- بقية ألعاب الغرف ما زالت أطواراً قديمة تعتمد على حالة يرسلها العميل؛ لا تُعامل على أنها مقاومة للغش أو محركات خادمية مكتملة. لا نرفعها إلى engine_version=2 قبل بناء واختبار محرك مستقل لكل لعبة.
- لا يوجد حالياً تكامل نموذج ذكاء اصطناعي أو مفتاح مزوّد AI في هذا المشروع. لا تضع مفاتيح Gemini أو OpenAI أو أي مفاتيح سرية داخل ملفات الواجهة؛ أي ميزة AI مستقبلية يجب أن تمر عبر Edge Function مع تحقق الهوية، وحدود استخدام، وحماية من حقن التعليمات، وتقليل البيانات المرسلة للمزوّد.
## المحركات الخادمية لألعاب الغرف
- تُدار غرف الألعاب الجديدة على المحرك الخادمي الإصدار الثالث، وتبقى لعبة تخمين الرقم على الإصدار الثاني. كل حركة تمر عبر بوابة Edge Function موثّقة، والعميل لا يرسل نتيجة الفوز أو رمية النرد أو حركة القطعة باعتبارها حقيقة.
- الأيدي الخاصة للدومينوا وكروت الألوان، وبطاقات برا السالفة، تحفظ في جداول خاصة وتُسترجع لكل لاعب بعد التحقق من عضويته. لا تُرسل الأيدي إلى بقية أعضاء الغرفة.
- وجود اللاعب يُحدّث بنبضات اتصال، وتبقى مقاعد اللاعبين في الجولة النشطة حتى يقدرون يرجعون للحساب نفسه. تُرفض التحديثات المتزامنة القديمة بدلاً من الكتابة فوق حركة أحدث.
- الغرف القديمة لا تُمسح ولا تُحوّل أثناء جولة حية. يستطيع المضيف ترقية الغرفة بين الجولات بعد اكتمال إجابات الطور الجماعي، أو بعد انتهاء اللعبة.
- الطاولي الحالية **مبسّطة** وليست تطبيقاً كاملاً لكل قواعد طاولة الزهر الرسمية. بقية الأطوار تعتمد القواعد المبينة داخل واجهة اللعبة.
- اختبارات الانحدار موجودة في `scripts/test-authoritative-room-engines.sql` وتعمل داخل معاملة تنتهي بـ`ROLLBACK`. لا تعتمد أي لعبة أو تغيّر إصدار الغرف قبل نجاح هذه الاختبارات.
